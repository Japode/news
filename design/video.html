Controle de versão

A IA escreve tanto código que a Anthropic precisou ir além do Git

Os merges diários no repositório principal da Anthropic passaram de 2.500 para mais de 30 mil em quatro meses. O Git não deu conta, e a empresa construiu o Scion.

De onde vêm os fatos

Todo número e toda afirmação do vídeo vêm de um único documento:

[1] Anthropic, “Redesigning source control at Anthropic”, blog de engenharia, 13/10/2026, atualizado em 15/10/2026. Em inglês.

Em setembro de 2026, a Anthropic, a empresa que cria o Claude, juntava mais de 30 mil mudanças de código por dia no repositório principal. O Git, a ferramenta que guarda a história de quase todo software do mundo, não deu conta.[1]

Trinta mil por dia

Em maio, eram cerca de 2.500 merges por dia. Quatro meses depois, mais de 30 mil. É o efeito dos agentes de inteligência artificial escrevendo código.[1] A própria Anthropic resume o problema assim: o gargalo agora é toda a infraestrutura feita na escala humana, como controle de versão, build e integração contínua. Escrever código deixou de ser a parte lenta.

Feito para outro mundo

O Git nasceu em 2005, escrito por Linus Torvalds para o kernel do Linux. Cada pessoa tem a história inteira no próprio computador, trabalha offline e sincroniza quando quiser. A Anthropic usava o Git de um jeito centralizado: um único repositório gigante, com a integração contínua puxando código o tempo todo. Nas palavras da empresa, as propriedades que fazem o Git excelente para o trabalho distribuído e offline estavam atrapalhando a escala.[1]

Onde o Git quebrou

Só a história do branch principal tinha quase 100 GB. A integração contínua fazia cerca de 25 milhões de checkouts por dia. Se cada um baixasse tudo, seriam mais de 600 petabytes de tráfego por dia.[1] Clone raso, clone parcial e sparse checkout foram usados, e a empresa chegou a manter centenas de espelhos internos do Git só para aguentar a carga. Quanto mais rápido entravam as mudanças, mais difícil ficava manter tudo de pé.

O servidor no centro

No Scion, quem guarda e trabalha a história é o servidor. Commit, merge, rebase, blame e diff acontecem lá; como diz a Anthropic, não sobra nada para dar push. A unidade de trabalho deixa de ser o commit e vira o changeset, uma entrada num write-ahead log que guarda só os arquivos que mudaram. Os metadados ficam no Spanner, o conteúdo num armazenamento em nuvem, e mover um branch é uma única troca atômica numa linha do banco. Para responder blame e histórico, o servidor calcula o que a empresa chama de derived data.[1]

Só o que você precisa

A máquina de quem trabalha não baixa mais o repositório inteiro. O cliente pede só as árvores e os arquivos de que precisa, e o checkout pode ser virtual: o arquivo aparece no disco na hora em que alguém precisa dele. No caminho há três camadas de cache: um daemon em cada máquina, um cache por região e, só no fim, o servidor. Cada camada responde sozinha mais de 99% dos pedidos, e não existe packfile para manter.[1]

Sete pessoas, cinco meses

A infraestrutura do Scion ficou 200 vezes menor que os antigos espelhos do Git, em processador e memória. Os checkouts de testes e de pesquisa passaram de minutos para segundos, e a integração contínua ganhou 25% de capacidade. Tudo foi feito por uma equipe de sete pessoas, em cinco meses, enquanto os merges diários se multiplicavam por dez. Junto veio o Antique, uma nova ferramenta de revisão de código. Uma versão do pipeline de importação reescrita pelo Claude usava 20 vezes menos memória e era 4 vezes mais rápida, e hoje instâncias do Claude, os “superfans”, acompanham cada uma um componente do sistema.[1]

Nos ombros de gigantes

A Anthropic dá o crédito ao Piper, do Google, e ao Sapling, da Meta, em especial ao Mononoke, o servidor do Sapling, que criou o modelo de dados Bonsai e muitas das técnicas usadas no Scion. E o seu Git continua aí: segundo a empresa, o Scion não é um substituto do Git para uso geral, e foi feito para monorepos realmente enormes. O plano é compartilhar as ideias para que outras equipes levem parte delas para o próprio Git.[1]
